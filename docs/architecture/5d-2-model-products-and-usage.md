# 5D-2 动态模型产品、选择策略与 AI 用量

## 目标与业务边界

5D-2 将 5D-1 的“平台模型连接与能力路由”补齐为可运营的模型产品层：聚合平台负责提供动态 Model ID，平台管理员负责验证、发布、定价和灰度，普通用户只看到可用的逻辑模型产品，不接触平台 API Key。

本阶段保持两条模型来源：

- 平台模型：由开工吧统一采购与托管，用户无须配置密钥；可在对话中选择“智能匹配”或一个已发布模型。
- 企业自有模型（BYOK）：保留 StaffDeck 原有配置入口和调用路径；密钥归企业所有，用量与平台计费分开记录。

AI 需求分析、AI 匹配、AI 报价草案和争议证据摘要均通过统一网关调用。AI 只能整理、推荐和起草：乙方仍需确认报价；匹配只能重排系统给出的候选；证据摘要不得生成退款、放款或责任裁决。

## 5D-2.0 至 5D-2.8 实现

### 5D-2.0 基线与备份

- 基于 5D-1 稳定分支开发，保留原 StaffDeck 功能、路由、Icon 与企业 BYOK 数据。
- 开发前执行 SQLite 在线备份，禁止用本地数据库覆盖线上数据库。
- 新 Alembic 版本为 `20260803_0017`，下修订为 `20260803_0016`。

### 5D-2.1 动态模型目录

- 新增 `ai_provider_catalog_models`，记录聚合平台当前可用 Model ID、模型族、能力、上下文长度、首次/最后发现时间和可用状态。
- CRUN 默认 LLM Base URL 为 `https://api.crun.ai/api/v1`，通过 `GET /models` 动态发现模型；认证信息只在服务端使用。
- 同步是幂等的：新增、更新和已下线模型分别计数；目录中非聊天模型不会生成聊天产品草稿。
- 连接类型是开放枚举，除 CRUN 外可继续添加第二家或更多 OpenAI 兼容聚合平台。

### 5D-2.2 模型产品层

- `ai_model_products` 是用户看到的逻辑模型，和供应商 Model ID 解耦。
- `ai_model_product_deployments` 允许同一个逻辑产品绑定多个聚合平台部署，并按优先级故障切换。
- 动态同步只创建隐藏、停用的部署与产品草稿；至少一个部署验证健康后才能发布。
- `ai_model_product_access` 支持按租户或用户灰度。管理员界面提供“灰度发布 / 全量发布 / 下架”。
- 用户接口只返回已发布、当前账号可访问且至少有一个健康部署的模型产品。

### 5D-2.3 员工与会话模型策略

- `agent_model_policies`：数字员工可配置智能匹配、指定平台模型或企业自有模型。
- `chat_session_model_selections`：对话框选择只影响当前会话，并在刷新后恢复。
- 解析顺序为：会话显式选择 → 员工策略 → 原有企业默认模型/绑定 → 平台智能路由。
- 任何租户、用户或员工越权选择都会在服务端拒绝，不能只依赖前端隐藏。

### 5D-2.4 Token、价格与额度账本

- `ai_price_versions`：不可修改的价格版本，按生效时间为历史调用冻结成本快照。
- `ai_usage_events`：逐次调用记录输入、输出、缓存、推理和总 Token；只保存内容哈希，不保存提示词或回复原文。
- `ai_quota_accounts` 与 `ai_quota_ledger`：额度账户、预占、释放、消耗和发放流水；幂等键防止重复记账。
- `ai_usage_daily`：按日、账号、员工、模型和来源汇总，供运营和用量页面查询。
- 企业 BYOK Token 会被记录，但不计入平台模型点数；没有价格版本的调用记录 Token，费用为 0，等待管理员补充后续价格版本。

### 5D-2.5 统一业务 AI

- AI 需求分析：输出完整度、缺失信息、建议交付物、验收标准和风险提示，不改变预算与明确约束。
- AI 匹配：只能重排真实候选服务，不得虚构服务商；模型不可用时保留确定性匹配结果。
- AI 报价：只能生成服务范围、排除项、工期、里程碑和验收草案；总价仍由交易系统计算，且必须经过乙方确认。
- AI 证据摘要：中立整理主张、证据时间线、矛盾和缺失材料；平台争议处理、调解、裁决、复核与结案状态机不由 AI 控制。

### 5D-2.6 用户与管理员界面

- 对话模型下拉：动态展示智能匹配、全部已发布平台模型和企业自有模型，不再把模型列表写死为四个品牌。
- 新建数字员工：保留三种创建方式，并增加员工默认模型策略。
- AI 用量：展示剩余额度、已消耗点数、平台/BYOK Token、30 天趋势和按员工汇总。
- 管理员模型配置：保留原企业 BYOK 区域；平台区域增加模型目录同步、部署验证、模型产品灰度/全量发布。

### 5D-2.7 迁移与回归

- 迁移需通过 SQLite 与 PostgreSQL DDL 测试、升级/降级/重放测试和数据库完整性检查。
- 权限回归覆盖普通用户不能读取连接、密钥、价格或租户级用量；管理员接口也只返回密钥掩码。
- 会话选择、员工策略、产品发布、目录重复同步、用量幂等和旧路由需要自动化测试。
- 完整回归包含后端全量、前端全量、i18n、环境配置检查和生产构建。

### 5D-2.8 灰度、监控与回滚

- 首次只向测试租户灰度发布一个低成本聊天模型；验证对话、四类业务 AI、Token、成本、额度和审计后再扩大。
- 第二家聚合平台作为独立备用部署，受控模拟主连接超时、429 和 5xx，验证跨平台切换。
- 监控至少包含请求量、成功率、429/5xx、首字/总耗时、Token、供应商成本、计费点数、余额预警和回退次数。
- 密钥必须在 CRUN 等供应商后台配置服务器 IP 白名单和额度上限，不得写入仓库、前端构建物、日志或测试数据。

## 管理员操作顺序

1. 在“模型配置 → 平台默认 AI 服务 → 聚合平台”添加 CRUN 或其他连接。
2. 点击“同步模型目录”，确认发现数量和生成的部署/产品草稿数量。
3. 在“平台模型”逐个验证计划使用的 Model ID；验证会执行普通文本与结构化 JSON 请求。
4. 为已验证部署创建不可变价格版本。
5. 在“模型产品”先选择“灰度发布”，仅让当前测试租户看到。
6. 配置 `agent_chat` 和四类业务能力的主备路由，完成受控验收。
7. 观察监控与账本，再决定全量发布；不应一次发布聚合平台返回的全部模型。

上线前先备份数据库并记录当前 Alembic 版本。部署兼容代码后执行：

```bash
cd backend
.venv/bin/alembic upgrade 20260803_0017
```

逻辑回滚优先：下架模型产品、停用能力路由和部署、停用聚合连接，企业 BYOK 路径继续可用。保留 0017 的用量与账本数据用于审计。只有未写入真实配置和用量的测试环境才可执行数据库 downgrade；生产产生账本后不得直接降级删除表。

- 未用 AI 代替乙方报价确认、甲方选标、合同确认、验收、退款、放款或平台争议处理。
- 未部署生产环境；真实密钥录入、IP 白名单和灰度开关必须在部署后由授权管理员执行。
