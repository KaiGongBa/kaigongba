# 5D-1 平台默认大模型与统一 AI 网关

## 目标与边界

本阶段提供平台托管的默认 AI 能力，使没有自带大模型配置的用户也能使用数字员工和后续业务 AI 功能，同时保留企业自有模型（BYOK）的优先级。

平台连接与模型分开管理：一个聚合平台连接只保存一份服务端 API Key，可以挂载豆包、DeepSeek、GLM、Kimi、通义千问、MiniMax、百川、混元、文心等多个 Model ID；也可以同时配置多家聚合平台，并按能力设置跨平台主备路由。

本阶段不包含：生产密钥录入、真实额度采购、业务 AI 提示词定稿、生产环境开关切换。AI 需求分析、匹配、报价和证据摘要应在后续阶段通过统一网关接入，不能各自直连模型供应商。

## 已实现架构

### 配置与数据

- `ai_provider_connections`：聚合平台/直连服务连接、加密密钥、验证和启停状态。
- `ai_model_deployments`：连接下的 Model ID、模型族、能力标签、协议参数、价格和健康状态。
- `ai_model_routes`：能力到模型的优先级、超时、重试和启停策略。
- `ai_model_invocation_audits`：调用来源、请求哈希、状态、尝试次数、耗时和错误码；不保存提示词与回复原文。
- Alembic 版本：`20260803_0016`，从 `20260802_0015` 升级。

API Key 使用现有加密模块写入数据库，读取接口只返回掩码；平台连接、模型、路由与审计接口仅允许平台管理员访问。

### 能力目录

| 能力 ID | 用途 |
| --- | --- |
| `agent_chat` | 数字员工与开小花对话 |
| `structured_generation` | 结构化 JSON 生成 |
| `demand_analysis` | AI 需求分析 |
| `matching` | AI 服务匹配 |
| `quote_draft` | AI 报价草案 |
| `evidence_summary` | 争议证据摘要 |
| `knowledge_processing` | 知识整理 |
| `skill_distillation` | Skill 整理与生成 |

### 运行选择规则

1. 显式指定且可用的企业模型。
2. 企业默认模型（BYOK）。
3. 对应能力的平台路由，按优先级从小到大选择。
4. 路由无可用目标时返回明确的缺少模型配置错误，不伪造 AI 结果。

统一网关支持同一模型重试和跨聚合平台切换，并记录内容最小化审计。现有 StaffDeck 数字员工执行已获得平台默认模型解析能力；新增业务 AI 必须通过 `AIModelGateway` 调用。

## 平台配置流程

1. 使用平台管理员进入“模型配置”。
2. 在“聚合平台”添加连接名称、平台类型、协议、Base URL 和 API Key。新连接默认停用且未验证。
3. 在“平台模型”为连接添加实际 Model ID，选择模型族和可承载能力。新模型默认停用。
4. 执行“验证并启用”。验证同时检查普通文本与结构化 JSON；成功后连接与模型才可启用。
5. 在“能力路由”分别配置主模型和备用模型。建议主路由优先级 `100`，备用路由 `200`、`300`。
6. 先只启用 `agent_chat` 和 `structured_generation`，用受控账号灰度；业务能力在提示词、结构化输出和人工确认规则验收后再逐项启用。

建议初期至少使用两家互相独立的聚合平台。不要把同一家聚合平台中的两个 Model ID 当作完整的灾备方案。

## 上线步骤

1. 备份生产数据库、对象存储配置和当前环境变量，记录应用提交号和 Alembic 版本。
2. 先部署兼容 0015/0016 的应用代码，再执行 `alembic upgrade 20260803_0016`。
3. 确认四张新表存在，原 `model_configs` 数据与默认模型未改变。
4. 登录管理员页面，确认“平台默认 AI 服务”四个页签正常，原企业 BYOK 列表仍可使用。
5. 录入第一家聚合平台真实密钥，添加一个低成本测试模型并完成验证。
6. 先在隔离测试环境启用 `agent_chat` 路由，验证无 BYOK 用户可以对话，有 BYOK 用户仍优先使用自有模型。当前平台路由启用后会服务全部无 BYOK 用户，因此在共享生产环境启用前必须安排维护窗口，或先补充按账号/租户放量规则。
7. 增加第二家聚合平台备用路由，受控制造主路由失败，确认切换、错误码和审计记录。
8. 观察错误率、首字耗时、总耗时和费用后，再扩大账号范围。

## 回滚方案

优先使用逻辑回滚，不立即降级数据库：

1. 停用全部平台能力路由。
2. 停用对应模型和聚合平台连接。
3. 应用回滚到上一稳定提交；原企业 BYOK 路径继续工作。
4. 保留 0016 表和调用审计用于复盘。

只有在确认四张新表没有需要保留的配置和审计数据时，才能执行 Alembic downgrade 到 0015。生产已录入真实配置后不得直接降级删表，应先导出并加密归档。
