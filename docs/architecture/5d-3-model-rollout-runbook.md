# 5D-3 平台模型真实接入与灰度发布运行手册

## 范围

本阶段把 5D-2 的统一 AI 网关接入真实聚合平台。CRUN 是首个连接，后续聚合平台继续使用相同的连接、部署、模型产品、能力路由和用量账本，不在业务代码中硬编码供应商。

CRUN OpenAI 兼容 Base URL：`https://api.crun.ai/api/v1`。目录同步访问 `/models`，语言模型调用访问 `/chat/completions`。

## 安全前置

1. 撤销任何曾出现在聊天、终端或工单中的 API Key。
2. 创建开工吧服务端专用 Key，并在 CRUN 设置额度、频率和生产服务器 IP 白名单。
3. 只在管理端“平台默认 AI 服务”录入新 Key；禁止写入 `.env`、Git、前端变量、部署脚本和文档。
4. 预发、生产必须设置独立 `APP_SECRET`，否则应用启动校验应失败。
5. 迁移前使用数据库原生备份；SQLite 在线环境使用 `.backup`，PostgreSQL 使用 `pg_dump`。

## 发布顺序

1. 新建 CRUN 平台连接，确认返回值只有脱敏 Key。
2. 同步完整目录；首次同步生成隐藏的部署和产品草稿。
3. 重复同步一次，确认不产生重复记录。
4. 选择少量语言模型执行基础验证：中文文本、流式输出、结构化 JSON。
5. 按真实用途执行能力认证：需求分析、匹配、报价草案、证据摘要、知识整理、Skill 生成。
6. 为验证通过的部署创建价格版本。
7. 为演示租户创建当月测试额度。
8. 建立能力主备路由；关键能力至少两个不同连接或不同上游部署。
9. 将模型产品以 allowlist 方式灰度给演示租户。
10. 完成双账号业务回归后再全量发布。

## 认证规则

- `agent_chat` 必须同时通过普通文本和流式输出。
- 其他业务能力必须返回符合对应字段约束的 JSON object。
- `skill_distillation` 必须生成包含 `name` 和 `arguments` 的结构化 `tool_call`。
- `evidence_summary` 只能整理事实和缺失材料；出现裁决、退款或放款决定字段即认证失败。
- 每次认证生成新的不可修改证据；最新一次结果决定能力是否可路由。
- 未认证能力不能建立启用状态的路由。

## 目录同步规则

- 图片、视频、音频、TTS、Embedding 和 Rerank 模型保留目录记录，但不生成对话模型产品。
- 上游目录消失的模型标记为 `unavailable`，关联部署立即停用，历史订单和用量记录不删除。
- 模型重新出现后回到 `unknown`，必须重新验证才能启用。
- 产品必须有健康、已认证 `agent_chat` 的部署后才能发布到用户模型下拉框。

## 业务路由

平台管理以下能力，存在健康平台路由时优先使用平台模型：

- 结构化生成
- AI 需求分析
- AI 服务匹配
- AI 报价草案
- 争议证据摘要
- 知识整理
- Skill 整理与生成

数字员工普通对话继续尊重会话选择和企业自有模型；未明确选择时才使用平台兜底。

## 用量与额度

- 非流式与流式调用都写入统一用量事件。
- 记录输入、输出、缓存、推理和总 Token，以及供应商请求 ID、模型部署、会话、用户、员工和业务能力。
- 价格采用不可修改的版本记录；新价格只影响生效时间之后的请求。
- 额度发放和扣减必须带幂等键；请求重放不得重复发放或重复扣减。
- 无价格版本时仍记录 Token，但成本和额度为零，并标记为未计价。

## 灰度验收

1. 管理员能同步目录、查看认证和调用审计。
2. 灰度租户能看到已发布模型，其他租户不可见。
3. 对话端能在智能匹配、平台模型和企业自有模型之间切换。
4. 会话选择持久化，新会话继承数字员工策略。
5. 需求分析、匹配、报价草案、证据摘要均通过真实模型完成。
6. 报价必须经乙方确认；证据摘要不得生成裁决。
7. 主模型超时、429 或 5xx 时，在未输出内容前切换备用模型。
8. 重复请求不重复写用量或扣额度。

## 回滚

1. 先下架模型产品并停用能力路由，用户下拉框会自动隐藏平台模型。
2. 禁用聚合平台连接，不删除连接、部署、认证、价格、用量和审计数据。
3. 回滚应用版本；只有在确认新表没有生产数据时才降级数据库迁移。
4. 如怀疑 Key 泄露，先在供应商侧撤销 Key，再更新平台连接。
