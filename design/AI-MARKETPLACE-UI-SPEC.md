# 开工吧增量 UI 设计说明

版本：UI 确认稿 v1
范围：新增交易、供给、开放 Skill 市场、企业协作和平台监管页面
约束：本轮只交付 UI 与页面逻辑，不修改生产代码

## 1. 设计结论

- 以当前开工吧产品为唯一视觉基准：白色侧栏、浅灰工作区、红色开工吧 Logo、黑色主操作、克制的蓝色功能提示和浅黄色提醒。
- 基于 StaffDeck 开源项目的原有功能及图标只保留、不删减；产品界面统一使用“开工吧”品牌。新功能以新分组、二级页签或详情工作区增量接入。
- 用户不持有永久“甲方/乙方”身份。身份由当前订单关系决定：调用他人服务时是需求方；自己的 AI 员工被调用时是服务方。
- 同一企业内调用自有 AI 员工生成内部任务，不生成商业订单、支付单或合同。
- 只有支付采用演示流程；需求、报价、合同确认、订单、交付、验收、争议、Skill 发布等均按真实业务数据和真实状态设计。
- AI 报价只能生成草稿，必须经服务方管理员确认后才能发送。
- “仲裁”统一命名为“平台争议处理”。AI 只能整理证据和生成摘要，裁决由有权限的平台人员完成。
- 第三方 Skill 允许开放发布、检索和安装；执行前必须完成权限清单、版本摘要、验证、安全检查和运行时隔离。

## 4. 主业务链路

### 直接购买已上架服务

U01 → U02 → U05 → U10 → U11 → U12 → U13/U14 → U15

### 发布需求并比价

U06 → U07 → AI 匹配 → U08 → U09 → U10 → U11 → U12 → U13/U14 → U15

### AI 服务供给

开工吧现有 AI 员工 → U17 → U18 → P01 → U01/U02 → U20/U14

### 第三方 Skill 供给

U17 → U19 → P01 → U03/U04 → 安装到企业或 AI 员工 → 开工吧技能执行

### 平台争议处理

U15 发起争议 → 自动冻结结算 → P03 归档证据并分配处理人 → 调解/裁决 → 复核 → U13/U14 展示结果

## 5. 关键状态与权限

### 服务

草稿 → 待审核 → 已上架 → 已下架
待审核也可进入审核不通过并返回草稿修改。成交订单永久引用成交时服务和 SOP 快照。

### 报价

AI 草稿 → 待服务方确认 → 已发送 → 已更新/已撤回 → 已选中/未选中。
任何 AI 生成内容在“已发送”之前不对需求方可见。

### 订单

待签约 → 待付款 → 已付款 → 进行中 → 待验收 → 已完成。
分支状态包括争议中、已取消、退款中。订单变更必须产生结构化变更单并由双方确认。

### 里程碑

待开始 → 进行中 → 待提交 → 待验收 → 已验收。
修改中、争议中是受控分支，不能仅靠聊天消息改变状态。

### Skill

草稿 → 待验证 → 待审核 → 已发布 → 已停用/已下架。
高风险权限需要额外审核；安装时再次向使用方展示权限和数据范围。

### 可见性

- 需求方只看服务范围、订单进度、交付物和经过脱敏的 SOP 摘要。
- 服务方可看自身提示词、知识库、密钥、内部任务和成本。
- 平台人员按岗位权限查看监管所需数据，敏感查看和资金操作全部审计。
- 开工吧 AI 执行引擎只能回传任务状态、结果和文件，不能直接验收、退款、放款或裁决。

## 6. 交互与实现约束

- 所有会改变合同、价格、范围、工期、交付和资金状态的动作都使用结构化表单、二次确认和操作回执。
- 消息聊天只负责沟通，不承载交易状态真值。
- 服务、报价、合同、订单变更、交付物和 Skill 都显示版本号、创建人、时间和摘要。
- 文件列表展示归属订单/里程碑、版本、提交人、可见范围和临时下载有效期。
- 真实支付接入时保留 U11/P04 的业务抽象，仅替换渠道适配器和页面中的“演示”组件。
- 不共用超级管理员账号；退款、放款和争议裁决采用经办/复核分离。

## 7. 本轮确认边界

本目录内 26 张 PNG 为新增页面的唯一 UI 确认依据。确认前不接入路由、不修改组件、不迁移数据库、不改动开工吧现有菜单、功能和图标。`design/archive/` 仅保存被否决的历史视觉方向，不属于确认范围。确认后再按页面编号拆分前端路由、组件、API、权限和状态机实现任务。
